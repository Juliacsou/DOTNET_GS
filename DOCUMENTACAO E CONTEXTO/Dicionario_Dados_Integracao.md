## Contratos criticos entre os backends

### Identidade JWT

- Java cria `TB_USUARIO.ID_USUARIO` numerico (Oracle `NUMBER(19)`); o `sub` do JWT e sua representacao decimal em string, por exemplo `"123"`.
- Java assina o JWT (recomendado RS256). .NET valida assinatura, `iss`, `aud`, `exp` e `roles`; extrai `sub` para autoria. NUNCA usar `ID_USUARIO` enviado pelo cliente em cadastro de ocorrencia/comentario/voto.
- `CIDADAO` participa; `ADMIN` somente consulta relatorios. Contas visitantes nao existem no Oracle; GETs publicos sao acessiveis sem login.

### Consulta e RAG sob responsabilidade Java

1. Frontend envia ID da ocorrencia ao Java. Java valida JWT e consulta a **API .NET** para recuperar titulo, descricao, municipio e categoria.
2. Java filtra a view `VW_TRECHOS_RAG_APROVADOS` por `ID_MUNICIPIO` e `ID_CATEGORIA`. Os documentos retornam ID, texto do trecho, URL e data de verificacao.
3. Spring AI usa os trechos como contexto, gera orientacao estruturada e evita contatos/horarios nao confirmados. **Nenhuma chamada LLM ocorre no .NET/Oracle.**
4. Java salva o resultado usando `PKG_BASE_IA.PR_REGISTRAR_ORIENTACAO`, referenciando uma fonte aprovada quando `ESTADO_ORIENTACAO` for `DISPONIVEL` ou `PARCIAL`. Outras fontes usadas tambem podem ser vinculadas a `TB_ORIENTACAO_FONTE`, sujeitas ao trigger.
5. Sem fonte validada: estado `SEM_FONTE` e ID de fonte nulo. Sem municipio confiavel: `LOCALIDADE_NAO_CONFIRMADA`. Qualquer horario/contato nao fundamentado deve permanecer ausente.

**Exemplo de consulta para RAG — apenas municipio Sao Paulo e categoria Arvores**:

```sql
SELECT ID_TRECHO, ID_FONTE, TITULO_FONTE, URL_FONTE, TEXTO_TRECHO, DT_VERIFICACAO
  FROM VW_TRECHOS_RAG_APROVADOS
 WHERE ID_MUNICIPIO = 1 AND ID_CATEGORIA = 3;
```

**Exemplo de chamada Java/Oracle para registrar resposta PARCIAL**:

```sql
DECLARE v_id NUMBER;
BEGIN
  PKG_BASE_IA.PR_REGISTRAR_ORIENTACAO(
    P_ID_OCORRENCIA => 1, P_ID_USUARIO => 1, P_ID_SERVICO => 3,
    P_TEXTO_ORIENTACAO => TO_CLOB('Contato 156 conforme fonte oficial; horario nao confirmado.'),
    P_MODELO_LLM => 'DEMO', P_ESTADO => 'PARCIAL', P_ID_FONTE => 3,
    P_FL_PUBLICA => 'N', P_ID_ORIENTACAO => v_id
  );
  DBMS_OUTPUT.PUT_LINE(v_id);
END;
/
```

### Comunidade sob responsabilidade .NET

- `TB_OCORRENCIA` conserva `ID_USUARIO` mesmo quando `FL_ANONIMO = S` e a view publica mascara seu nome. A consulta "Minhas ocorrencias" usa ID de autor vindo do JWT.
- `TB_ATUALIZACAO` armazena comentario e relato com anonimato; `TB_MIDIA` armazena apenas referencias a fotos de ocorrencias ou atualizacoes.
- `PKG_COMUNIDADE.PR_REGISTRAR_ATUALIZACAO` aplica a regra dos 2 usuarios diferentes por ciclo, com bloqueio da linha e historico de status. O ADMIN nunca faz isso.
- `TB_REQUISICAO_IDEMPOTENTE` suporta controle de repeticao pelo .NET. Arquivos reais nao estao no Oracle.

### Observacoes de implementacao

- Java JPA: `@Id`/`@GeneratedValue(strategy = GenerationType.IDENTITY)` para colunas IDENTITY; `CLOB` exige mapeamento de texto grande adequado; `TB_USUARIO.SENHA_HASH` jamais sai no JSON publico.
- A view de conhecimento RAG demonstra recuperacao por metadados e texto. Se a disciplina exigir indexacao semantica, embeddings/vetor devem ser implementados no Java, sem mudar o dominio .NET.
- Antes de deploy real, separar credenciais e permissoes de banco para Java e .NET; modelos e packages nao validam sozinhos o JWT.
- Exemplos de contatos na base sao majoritariamente ficticios; apenas queda de arvore em Sao Paulo tem fonte verificada na carga inicial, sem horario presumido.
- Na entrega academica, testar a compilacao no Oracle, integrar com o frontend e declarar uso de IA conforme o enunciado.
